NPM package for Node.js

Build WhatsApp bots in TypeScript with one API over Baileys and whatsapp-web.js.

Typed commands and middleware, a signed plugin sandbox, multi session management, audit logs, and secret redaction. Headless library, CLI, and starter templates.

Install View on GitHub

MIT license. Node.js 20 or newer. ESM and CommonJS.

Section 03: Install

Install

Add the core package to a Node.js project.

$ npm i @baehaqirafly3/bot-wa
CLI:
npm i -g @baehaqirafly3/bot-wa-cli
New project:
npm create @baehaqirafly3/bot-wa@latest
Testing:
npm i -D @baehaqirafly3/bot-wa-testing

The package is in active development. Pin exact versions until 1.0.

Section 04: Feature grid

What is in the box

Six parts that every serious WhatsApp bot ends up needing.

Adapters

One API, two engines

Write commands once. Switch between Baileys and whatsapp-web.js with a config value. Each engine sits behind the same adapter contract and the same contract tests.

Domain

Typed commands and middleware

Aliases, namespaces, flags, cooldowns, and permission levels from guest to owner. Middleware runs in deterministic priority order, and the context is typed end to end.

Plugins

Signed plugin sandbox

Plugins declare permissions in a manifest. The loader checks the SHA-256 hash, the Ed25519 signature, and the publisher trust store before any code runs.

Sessions

Multi session management

Run several sessions in one process. Auth state in file, SQLite, or Redis. Backup, restore, and migrate sessions. Reconnect uses exponential backoff with jitter.

Security

Audit log and secret redaction

Both are on by default. Tokens, keys, and credentials are redacted before they reach any log sink. Sensitive actions are written to an audit trail.

Tooling

CLI and starter templates

A bot-wa CLI for sessions, plugins, config checks, and migrations. A generator with six templates, from a one file echo bot to a multi session setup.

Section 05: Engine support

Engine support

Two engines in v1, behind one adapter contract. Both are unofficial WhatsApp clients.

Engine Adapter status Planned in How it connects Notes
Baileys In development v0.2.0 WebSocket, no browser First adapter. Reference implementation for the contract.
whatsapp-web.js Planned v0.4.0 Browser automation with Puppeteer Loaded lazily, only when selected. Heavier on memory.

Both engines are unofficial. WhatsApp can restrict or ban accounts that use unofficial clients. Use a dedicated number for your bot.

Section 06: Code sample

A bot in a few lines

Illustrative example. API names are final from v0.3.0.

  1. Create a bot and choose the engine in config.
  2. Register a command with metadata. Help text is generated from it.
  3. Call start. Nothing connects before this call.
src/index.ts 
import { createBot } from "@baehaqirafly3/bot-wa";

const bot = createBot({
  engine: { name: "baileys" },
  session: { name: "main", storage: "sqlite" },
});

bot.command("ping", { description: "Check that the bot responds" }, async (ctx) => {
  await ctx.reply("pong");
});

await bot.start();

Section 07: Plugin model

How a plugin is verified

A plugin runs only if every check passes. A failed check is written to the audit log.

Permissions

read:message send:message access:storage access:network access:fs access:scheduler access:session admin:group

A permission that is not declared is not granted.

Section 08: Security

Security defaults

What the library does, stated plainly.

Redaction before logging

Fields like token, apiKey, password, and authorization, and patterns like JWT and Bearer tokens, are redacted before any sink receives the data.

Audit trail

Session changes, plugin installs and rejections, config changes, sensitive commands, rate limit hits, and sandbox violations are recorded with a correlation ID.

Verified plugins

Hash, signature, publisher trust, and engine range are checked before load. Permissions are granular and deny by default.

Isolated execution

Plugins run with a handler timeout and a memory limit. A plugin crash does not stop the bot.

Cryptographic randomness

Random values use crypto.randomBytes and crypto.randomUUID. The core avoids eval and new Function.

Supply chain checks

npm audit runs in CI. Each release ships a CycloneDX SBOM and npm provenance.

No telemetry

The library, the CLI, and the project generator send no usage data.

Read the security policy

No software is perfectly secure. Report vulnerabilities through the repository security advisories.
